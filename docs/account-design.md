## 0. 结论摘要

1. **底栏 4 项：书库 / 分类 / 发现 / 我的**。收藏不再是 tab（`Tab.FAVORITES` 注释掉即可恢复）。
2. **「我的」页** = 账户摘要卡（头像 / 昵称 / 称号 / 等级，**会员行仅在会员时出现**）
   ＋ 账号分组（收藏、我的留言）＋ 本机分组（最近浏览、下载任务、应用设置）＋ 版本号 / 退出登录。
3. **收藏 = 官方在线收藏**，页面沿用本机收藏页那套「收藏夹卡片 → 夹内 3 列网格」，
   交互按官方能力**逐级退化**（§4.3）：单夹、点了就是移动、非空夹不能删、没有夹排序。
4. **最近浏览 = 本机数据**（`t_jm_recent_album` + `RecentScreen`），
   入口、页面、`touchRecent` 写入全部保持现状——只把它从「更多」搬到「我的」。
5. 登录仍是**可选增强**：游客能看、能下、能读、能评论浏览；收藏 / 留言 / 资料要登录。
6. 本地收藏**逻辑一行不改**，只注释"生效点"（§10 清单，统一标记 `【本地UI隐藏】`）。

## 1. 事实基线

### 1.1 官方收藏模型（实测，详见 `docs/official-api-manga.md` §8）

**数据结构**

```json
// GET /favorite?page=1&folder_id=&o=mr
{
  "list": [ { "id": "1225147", "name": "…", "author": "…", "image": "",
              "category": {"id":"1","title":"同人"}, "category_sub": {"id":"3","title":"短篇"},
              "latest_ep": null, "latest_ep_aid": null } ],
  "folder_list": [ {"FID":"1780873","UID":"6404735","name":"本子"},
                   {"FID":"4090037","UID":"6404735","name":"AI"} ],
  "total": "178",
  "count": 20
}
```

**六条硬规则（每条都实测过，客户端必须照着写）**

| # | 规则 | 实测证据 |
|---|---|---|
| 1 | **单夹模型**：一本漫画同时只属于一个收藏夹 | `favorite_folder{type:move}` 是单选搬家；没有"追加到另一个夹"的接口 |
| 2 | **不能把漫画移出夹子**，只能取消收藏 | `move` 的 `folder_id` 传 `""`/`"0"` → `{"status":"fail","msg":"请选择移动的资料夹"}` |
| 3 | **非空收藏夹不能删** | `del` → `{"status":"fail","msg":"该收藏夹裡还有漫画，请先删除漫画","code":400}` |
| 4 | **加入时不能指定夹**（`folder_id` 被忽略） | `POST /favorite{aid,folder_id}` 返回 `type:"add"`，但夹内 total 仍 0 |
| 5 | **批量不可靠**：别用逗号拼多个 aid | `aid:"a,b"` 在两条都未收藏时返回 `type:"remove"`，实际状态与响应不符 |
| 6 | **写完立刻回读可能拿到旧值**（6 轮里出现 1 次） | 以写接口返回的 `type`/`status` 为准，不要用回读判定成功 |

**其它关键字段**

- `total` 是**字符串**（`"178"`）；`count` 是每页条数（20）。
- `folder_list` 只有 `{FID, UID, name}`：**没有数量、没有封面、没有排序字段、没有"默认收藏夹"**。
- 收藏列表项**没有** `update_at` / `liked` / `is_favorite`（所以收藏卡片不能显示更新时间）。
- 上限来自登录返回的 `album_favorites / album_favorites_max`（本账号 `178/600`）。

## 2. 产品定位与能力矩阵

| 功能 | 未登录 | 登录后 |
|---|---|---|
| 分类 / 搜索 / 详情 / 评论浏览 | ✅ | ✅ |
| 下载 / 阅读 / 导出 / 任务 / 书库 | ✅ | ✅ |
| **最近浏览（本机）** | ✅ | ✅ |
| 设置 / 线路 / 代理 | ✅ | ✅ |
| **收藏（账号）** | ❌ 入口可见，点 → 登录 | ✅ 官方在线收藏 |
| **我的留言** | ❌ 同上 | ✅ 列表 + 删除；详情页可发/回复 |
| **个人资料** | ❌ 同上 | ✅ 摘要 + 详细资料 |

**四条原则**：① 不阻塞（账号失败不影响本地功能）；② 不静默降级（写失败不许偷偷改本地数据）；
③ 一页一名（UI 上只有一个「收藏」，就是账号收藏；本机收藏已隐藏）；
④ 能力可见（未登录时入口照常显示，副标题「登录后可用」，点击 → 登录 → 直达目标）。

**账户摘要卡：只放必要信息**

| 元素 | 字段 | 显示条件 |
|---|---|---|
| 头像 | `photo` → `{img_host}/media/users/{photo}` | 总是（失败用"昵称首字"圆底；`AsyncImage` + `currentImageLoader()`，**不要改 `Cover`**） |
| 昵称 | `username` | 总是（超长省略） |
| 称号 | `level_name` | 总是（如"地上的月影"） |
| 等级 | `level` | 总是（`Lv.4`） |
| **会员状态** | `ad_free` + `ad_free_before` | **只有 `ad_free == true`**：`超级会员 · 至 {ad_free_before 的日期部分}`；**非会员整行不显示** |

- 未登录：卡片换成"灰色人像 + 未登录 + 一句话说明 + `[登录 / 注册]`"。
- 数据先读本机 profile 快照（DataStore），进页面后异步刷新 `GET /useredit/{uid}`。
- 「收藏」副标题 = `{album_favorites}/{album_favorites_max} · {folder_list.size} 个收藏夹`：
  前两个数来自登录返回，夹数用一次 `GET /favorite?page=1` 拿（可并行，失败显示「—」）。
- 「我的留言」副标题不预拉（点进去才算），拉到过就显示条数。
- 「最近浏览」副标题用本机计数（现有 `MoreViewModel.recentCount` 直接搬过来）。

## 4. 点收藏：与本地交互对齐 + 逐级退化（本轮核心）

### 4.1 本地收藏现在怎么交互（照代码逐条列）

1. 详情页「收藏 / 已收藏」按钮 → 打开 `FavoritePickerSheet`（**不是直接 toggle**）：
   - 说明文案：「点一下加入，再点一下移出；「移动到」会让本子只保留在该收藏夹里。」
   - 列出全部收藏夹，**每行一个方块勾选**（可多选：一本能在多个夹里）；
   - 每行右侧「移动到」按钮（单选语义）；
   - 底部「新建收藏夹」，展开输入框 + 确认。
2. 收藏页（tab）：收藏夹卡片（封面=夹内最近加入那本、名称、N 本、默认夹置顶、改名/删除）+ 顶部排序三选一 + 新建。
3. 删除非空收藏夹：**允许**，确认框写明"不删书库和已下载图片"。
4. 夹内页：复用书库布局，可多选「修改收藏夹」。
5. 书库有「收藏」筛选 chip。

### 4.2 账号侧能做到什么（实测）

| 本地能力 | 官方接口 | 能否对齐 |
|---|---|---|
| 点夹加入 | `POST /favorite`（toggle add）+ `favorite_folder{move}` | ✅ 但**两步请求**（`folder_id` 被忽略） |
| 点已选中的夹 → 移出该夹 | ❌ 只能取消收藏 | ❌ 语义退化 |
| 一本在多个夹 | ❌ 单夹 | ❌ 语义退化 |
| 「移动到」按钮 | ✅ `move` 就是移动 | ✅ 但"点夹"本身就是 move，按钮冗余 |
| 新建收藏夹 | ✅ `favorite_folder{add}` | ✅ 完全一致 |
| 改名 | ✅ `favorite_folder{edit}` | ✅ 完全一致 |
| 删除非空夹 | ❌ 服务端拒绝 | ❌ 退化 |
| 夹排序 | ❌ 无排序字段 | ❌ 退化 |
| 夹卡片数量/封面 | ⚠️ 需每夹额外一次 `GET /favorite?folder_id=X&page=1` | ⚠️ 可补拉（N+1） |
| 默认收藏夹置顶 | ❌ 无默认夹 | ⚠️ 用「全部收藏」代替 |
| 批量改夹 | ❌ 批量 aid 不可靠 | ❌ 不做 |
| 书库「收藏」筛选 | 账号收藏与本地库无关 | ❌ 隐藏 |

### 4.3 退化阶梯（一级一级退，先做尽量像本地的版本）

| 级 | 退化点 | 具体做法 | UI 文案 |
|---|---|---|---|
| **L0** | 保留两级结构与面板形态 | 详情页面板照抄本地：说明行 + 收藏夹列表 + 新建；收藏页照抄本地卡片列表 | 顶部说明改单夹版（见 §4.4） |
| **L1** | 多选 → 单选 | 收藏夹行改**单选**（选中态最多一个）。点未选的夹 = 加入并移入（未收藏先 `add` 再 `move`；已收藏只 `move`） | 「一本漫画只能放在一个收藏夹里，点一下就搬过去」 |
| **L2** | 「点已选中的夹=移出该夹」→「=取消收藏」 | 点已选中的夹 → `POST /favorite`（toggle remove），整本从收藏里移除 | 「再点一次会把这本从收藏里移出（官方没有"只移出夹"的接口）」 |
| **L3** | 删掉「移动到」按钮 | 点夹已经等于 move，再做按钮是重复 | — |
| **L4** | 删除非空夹 → 禁止 | 「删除」只在夹内 `total == 0` 时可点；非空置灰 + 说明 | 「夹里还有 N 本，先取消收藏才能删这个夹」（与服务器原文一致） |
| **L5** | 去掉夹排序 | 收藏页只留「新建」，不提供排序（服务端无排序字段） | — |
| **L6** | 数量/封面按需补拉 | 首屏先出「全部收藏」+各夹卡（数量「—」），后台并发（≤3）逐夹拉 `page=1` 补数量与封面，缓存 5 分钟；失败该卡保持「— 本」 | — |
| **L7**（不做） | 批量改夹 | 一期不做（`aid` 逗号分隔实测不可靠） | — |

> **为什么 L2 这么退化是对的**：官方数据模型里"在夹里"与"已收藏"是同一件事（都靠 `POST /favorite`
> 建/删收藏记录，`move` 只改夹）。所以"移出夹"在服务端根本不存在独立操作，退化成"取消收藏"是**唯一的**诚实做法。

**编辑（关键修正：全量提交）**

- 实测：`POST /useredit/{uid}` 是**整条记录覆盖**，没提交的字段会被写成默认值
  （只发 `nickName` → `birthday` 从 `0000-00-00` 变成 `1970-01-01`）。
- 所以流程：`GET /useredit/{uid}` → 用户改 → **把全部 24 个字段原样回传**（覆盖改动项），
  `password`/`password_confirm` 留空 = 不改密码（实测空密码字段不会改密码，登录仍正常）。
- 返回**更新后的整条资料对象**（不是 `{status,msg}`），可直接刷新展示与 profile 快照。
- 校验：昵称/姓名等 `maxLength 50`，长文本 `maxLength 200`；两次密码不一致 → 本地拦；
  只填一个新密码 → 本地拦；`birthday` 用日期选择器，**不要给用户改成空的机会**（空会被归一成 1970-01-01）。
- 会员相关行只在 `ad_free == true` 时显示（与 §3.2 一致）。

### 7.1 实现（2026-10-23）

- **回显 bug 的根因与修法**：官方 `InfoModal.tsx` 的输入框用
  `defaultValue={formData.nickName}`，而 `formData` 是 `GET /useredit` 回来后才填的 ——
  首帧渲染时还是空对象，`defaultValue` 之后**不会再更新**，所以已有资料永远填不进去。
  本工程改成：**进编辑页先 `GET`，加载完成前不渲染表单**；拿到 DTO 后一次性生成 Compose
  受控状态（`UserProfileForm`），并把它同时当作"提交底稿"——用户改的一定是刚拉到的原值。
  加载失败就整页报错 + 重试，**绝不让用户在空表单上编辑**。
- 编辑入口：资料页右上角「编辑」→ `Routes.ACCOUNT_PROFILE_EDIT`；返回时把缓存里的新资料
  同步回资料页（`AccountProfileViewModel.onScreenResumed`），「我的」摘要卡通过会话快照
  立刻显示新昵称（**昵称优先、没有才用登录名**）。
- 字段范围：官方 24 项全放（含改密码），分「账户 / 个人信息 / 位置信息 / 其他信息」四组。
  `username` / `email` **只读展示**（不在这 24 项里）；`gender` 也做成下拉。
- 生日：`0000-00-00` 与 `1970-01-01` 都显示成「未设置」（服务端把空日期归一成 1970，而且改不回去），
  选择器从 1900 年起、不给"清空"按钮；提交未设置时回传空串。
- 改密码：两个都空 = 不改；只填一个 / 两次不一致 → 本地拦住；长度 50 上限；
  客户端**不保存**新密码（只提交给服务端）。
- 「整条覆盖」的防线：`UserProfileForm.toSubmitFields()` 固定输出 24 个字段，
  单测核对键集合与顺序（少一项就会被服务端写成默认值）。

## 8. 登录 / 注册

（沿用 v2，要点如下。）

- **独立页面**（不是底部面板）：注册 6 字段 + 2 勾选、键盘要滚动、返回键要三级语义。
- 四模式单页状态机：登录 → 注册 → 验证码 → 回到登录；忘记密码独立入口。
- 登录字段：用户名 / 密码（`maxLength 50`、眼睛开关、`imeAction=Done` 直接提交）。
- 本地校验：空字段不发请求；注册校验两次密码一致、邮箱正则（抄官方 `pattern`）、性别必选、
  18+/条款勾选（**纯前端门槛**，官方也不提交这两个勾选）。
- 失败文案用服务端 `errorMsg` 原文；网络错误单独文案 + 「去改线路」。
- 注册成功 → 验证码模式；验证成功 → **用刚才的密码自动登录**，失败则回登录页并预填用户名。
- 重发验证码走**网页版** `/confirm`（`submit_action=resend` + `username` + `password`），60 秒冷却；
  App API 的同名分支在服务端是坏的，不能用。
- 登录成功 → 关页 → 有 `next` 走 `next`，否则回「我的」。

### 8.1 实现（2026-10-23）

| 项 | 实现 |
|---|---|
| 入口 | 登录页底部「注册新账号」；注册页独立路由 `jm/account/signup?next=&verify=` |
| 字段 | 用户名 / 密码 / 确认密码 / 邮箱 / 性别（Male / Female）+ 18+ 与协议勾选 |
| 本地校验 | 用户名 **≤15 字**（服务端实测上限，官方前端的 50 是错的）、两次密码一致、邮箱官方正则、性别必选、两个勾选必勾 |
| 注册 | `POST /register`（multipart，**不重试**）；失败展示服务端 `errors` 的**全部**条目 |
| 验证码 | `POST /confirm{username,numcode}`；成功后用刚才的密码自动登录 |
| 重发 | **网页版** `POST /confirm`（`submit_action=resend` + `username` + `password`）：App API 的 `/confirm{username,password}` 分支是坏的，稳定返回"无效的核查身份证"；客户端 60 秒冷却，服务端提示十分钟 |
| 返回键 | 验证码 → 注册表单 → 上一页；**注册已成功时表单只给「继续验证」**，避免重提交收到"用户名已存在"而卡死 |
| 已有验证码 | 登录页「继续验证」→ 同一路由 `verify=true`：直接填用户名 / 密码 / 验证码，验证成功同样自动登录 |
| 自动登录失败 | 进一个「验证完成」面板，按钮「去登录」，用户名预填到登录页 |
| 忘记密码 | 已实现（2026-10-25）：`POST /forgot{email}` → 服务端把「用户名 + 新密码」发到注册邮箱，**旧密码当场失效**；入口是登录页**密码框右下方的「忘记密码？ →」**（方案 B 改版）→ `Routes.FORGOT`；错误弹窗 / 本地校验页内提示，与注册页同一套 |
| 样式（2026-10-24 / 2026-10-25） | 登录 / 注册 / 验证邮箱三页统一「灰底白卡」：字段与主按钮在白卡内，次级链接（注册 / **继续验证** / 重发）在卡外灰底上；登录页的「忘记密码？ →」是例外，放在**密码框右下方**（卡内），底部只留**一行**：左「注册新账号」、右「继续验证」（左右贴边） |

> **返回字段的坑（真机实测）**：注册**成功**时 `errors` 是空字符串 `""`，失败时才是字符串数组。
> 客户端必须宽容解析（本工程 `LooseStringListSerializer`），否则会出现
> "账号已创建、邮件已发、App 却报 JSON 解析错误"。
>
> **错误展示（用户反馈，两轮定稿）**：
> - **服务端 / 网络错误**（注册、验证、重发验证码、登录、资料保存）→ `AlertDialog` 弹出，
>   正文可滚动；**多条错误逐行换行**（不用「；」拼接）。这类文案长、位置不固定，
>   放页内会把控件顶下去。
> - **本地能判断的错误**（空字段、两次密码不一致、邮箱格式、未选性别、未满 18、未同意协议、
>   改密码只填一个、验证码为空、「已有验证码」未填用户名 / 密码）→ **保持页内提示**，不弹窗；
>   有输入框的字段统一显示在**对应输入框下方**（`supportingText`，2026-10-24 与登录 / 注册页
>   对齐），性别 / 勾选没有输入框，用紧随其后的红字。
> - **验证码发送成功等一次性提示** → 保持验证码页上的一行文字，不弹窗。

## 9. 会话与安全

| 数据 | 位置 |
|---|---|
| `jwttoken` / `s`（AVS）/ 可选密码 | `SecretStore`（Keystore AES-GCM） |
| profile 快照（uid/username/**nickName**/level/levelName/photo/会员信息/收藏数/邮箱/loginTime） | DataStore JSON |
| 「保持登录」开关、上次用户名 | DataStore |

- **状态机**：`ANONYMOUS ⇄ SIGNED_IN → EXPIRED`（401 触发）。
- 401 表现：账号页顶部横幅「登录状态已失效 [重新登录]」，**不清空已显示数据**；
  「我的」页摘要卡灰掉 + 同一条横幅。
- 「保持登录」默认**关**（开启后加密存密码，401 时静默重登一次；密码无效则转 EXPIRED）。
  官方把本地有效期写死 1 小时，但实测 token 在短时间内多次请求都有效；**是否默认开，实现后再实测决定**。
- 退出登录：先 `POST /logout`（失败也照样清本地），确认框写明「只清本机登录状态，书库/下载/导出都不动，
  收藏与留言仍在服务器」。
- 不做多账号切换，不按账号隔离本地数据。

## 11. 状态与错误矩阵

| 场景 | UI | 下一步 | 禁止 |
|---|---|---|---|
| 未登录点收藏/留言/资料 | 跳登录页，`next` 记住目标 | 登录成功直达 | 弹"请先登录"就结束 |

| 登录：401 | 错误条（`errorMsg` 原文），输入保留 | 改输入重试 | 清空输入 |
| 登录：网络/超时 | 「网络异常，请检查线路后重试」+「去改线路」 | 重试 / 改线路 | 显示堆栈 |
| 注册：邮箱重复/格式错 | `data.msg` + 邮箱框红边 | 改邮箱 | 自造文案 |
| 验证码：错误/冷却 | `msg`；按钮禁用 + 倒计时 | 重输 / 等待 | 连点 |
| 账号页：401 | 顶部横幅「已失效 [重新登录]」 | 重新登录（回原页） | 静默清空列表 |
| 账号页：网络失败 | 保留内容 + 「加载失败 [重试]」 | 重试 | 整屏错误 |
| 收藏写操作 | 行内 loading + 禁点 | — | 重复提交、假装成功 |
| 收藏已满 | 顶部提示 + 服务端 `msg` | 去网页版整理 | 报"未知错误" |
| 删非空夹 | 按钮置灰 + 说明 | 先取消收藏 | 发请求试运气 |
| `move` 目标夹不存在 | 服务端 `msg` + 刷新夹列表 | 重选 | 静默失败 |
| 退出登录 | 确认框 | 本地立即置未登录 | 删本地数据 |

## 15. 本轮实测结论（已完成，细节见 `docs/official-api-manga.md`）

已实测并通过（用真实账号跑通一遍，含还原）：

- `POST /login` 字段与类型、`GET /useredit`、`POST /useredit`（**整条覆盖**已确认）。
- `GET/POST /favorite`、`favorite_folder` 的 `add/edit/move/del` 四种 + 三种失败形态。
- 单夹模型、`folder_id` 被忽略、不能移出夹、非空夹不能删、批量 aid 不可靠（§1.1 六条规则）。
- 漫画内容侧：`/album`、`/comic_read`、`/chapter`、`/album_download_2`、`/categories*`、`/search*`、
  `/forum*`、`/promote*`、`/latest`、`/serialization`、`/week*`、`/random_recommend`、`/hot_tags`。
- 两套签名（`2.1.11` / `2.0.13`）对账号接口都有效。

**测试对账号的副作用（已尽量还原，如实记录）**

| 项 | 结果 |
|---|---|
| 新增/删除的临时收藏夹 | 全部删除，`folder_list` 恢复为 `本子` / `AI` |
| 测试期间加入的收藏（114514/114515/114516/114517） | 全部取消，`total` 回到 **178** |
| 密码 | **未改动**（改密码字段留空，事后原密码登录成功） |
| `useredit.birthday` | ⚠ **从 `0000-00-00` 变成 `1970-01-01`**：测 `POST /useredit` 时服务端把空日期归一成 epoch，且改不回去（再传 `0000-00-00`/空串都会被归一）。这是唯一没能还原的字段，其余资料本来就是空值 |

**仍需在实现阶段确认的（少量）**

1. `POST /comment`、`/comment_delete`、`/like` 的真实响应（会产生公开数据，本次没跑）。
2. 注册/验证码/找回密码的真实响应与邮件可达性（会创建账号）。
3. 收藏上限满时的具体报错（当前 178/600，不方便制造）。
4. 401 之后 token 的真实寿命（官方本地写死 1 小时；决定「保持登录」默认值）。
